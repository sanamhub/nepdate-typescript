# ADR-0001: Package layout, toolchain and shared data

- Status: Accepted
- Date: 2026-09-25
- Updated: 2026-10-07 (hub ADR-0004: the patro (tithi, holidays, events) moves from the `nepdate/meta` subpath to the package
  `nepdate-patro`)
- Deciders: Sanam Pakuwal

## Context

The TypeScript port is one spoke of the NepDate family (hub ADR-0001). It must stay
dependency-free, tree-shake well, run on Node, Deno, Bun and browsers, and give the same results as
every other port. Hub [ADR-0004](https://github.com/sanamhub/nepdate/blob/main/docs/adr/0004-patro-in-a-separate-package.md) requires two installable units: the core `nepdate` and
`nepdate-patro`, in one repository, with one version.

## Decision

1. **Two npm packages, one repository, npm workspaces.** The root `package.json` is
   `"private": true`, has no `version`, lists `"workspaces": ["packages/*"]` and holds every
   `devDependency`.

   | Directory | npm name | Contents |
   |---|---|---|
   | `packages/nepdate` | `nepdate` | dates, conversion, arithmetic, formatting, parsing |
   | `packages/nepdate-patro` | `nepdate-patro` | tithi, public holidays, events (`shared/spec/PATRO.md`) |

   `nepdate-patro` lists `nepdate` in `peerDependencies` as `~X.Y.Z` (X.Y.Z = the release
   version, so the same minor), and in `devDependencies` as the exact `X.Y.Z`, which npm satisfies
   with the local workspace through a symlink (npm has no `workspace:` protocol; don't use it). A
   peer dependency means the app installs one copy of `nepdate`, so a `NepaliDate` passed to
   `info()` is the same class `nepdate-patro` was built against. Neither package has
   `dependencies`.
2. **The core never depends on events.** `packages/nepdate/package.json` names `nepdate-patro` in
   no dependency field, no file under `packages/nepdate/src/` imports it, and the packed core
   tarball contains no event data (CI checks the string `World Day Against Human Trafficking`, ADR-0004 §6).
3. **ESM only**, `"type": "module"`, `"engines": { "node": ">=22.12" }` in both packages (Node 20 is
   end of life; CommonJS users can `require()` ESM on 22.12+). No top-level `await`.
4. **`exports` map** with `types` first, one entry per package: `"."` → `dist/index.js`.
   `"sideEffects": false`, `"files": ["dist", "LICENSE", "NOTICE", "README.md"]`.
5. **Build with plain `tsc`** (one output file per source file, no bundler): the simplest tool that
   does the job, and nothing pre-1.0 in the release path. TypeScript 6.x as the dev dependency;
   move to 7 once its programmatic API is stable. Shared options in the root
   `tsconfig.base.json`: `strict`, `module`/`moduleResolution` `nodenext`, `target es2022`,
   `verbatimModuleSyntax`, `isolatedDeclarations`, `noUncheckedIndexedAccess`,
   `exactOptionalPropertyTypes`, `erasableSyntaxOnly`, `declaration`, `declarationMap`. Each
   package has `tsconfig.json` (`src/` and `test/`, `noEmit`) and `tsconfig.build.json` (`src/`
   only, emits `dist/`), both extending the base.
6. **Tools:** Biome (lint + format, one root `biome.json`), Vitest (tests, one `vitest.config.ts`
   per package), `publint` and `@arethetypeswrong/cli` (package shape), esbuild (size check only),
   mitata (benchmarks, in `bench/` only). All root `devDependencies`, exact versions.
7. **Shared data:** `shared/` is a read-only copy of the hub's `data/` and `spec/` with
   `shared/VERSION` (hub ADR-0001 §3). CI calls the hub's reusable `shared-check`; the weekly
   `shared-sync` runs `npm run codegen`.
8. **Generator:** one `scripts/codegen.ts` for both packages, run by `node` with its built-in type
   stripping (no `tsx`, no `ts-node`). It writes `packages/nepdate/src/calendar.gen.ts` from
   `shared/data/calendar/` and `packages/nepdate-patro/src/tables.gen.ts` from
   `shared/data/patro/`, each starting with `// Generated by scripts/codegen.ts. DO NOT EDIT.`
   `--check` fails on drift in either file.
9. **Dev commands** are root npm scripts calling `.ts` files the same way: `npm run ci` runs every
   gate (ADR-0004). Type stripping is on by default from Node 22.18, so development and CI use
   Node 24; Node 22.12 is only a runtime floor for users.

## Consequences

- Installing `nepdate` downloads and bundles no event strings; `nepdate-patro` is paid for only
  by apps that install it.
- Both packages work with `require()` on Node 22.12+ and with every ESM bundler.
- The two packages always share a version and are released from one tag (ADR-0005).
